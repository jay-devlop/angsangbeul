# 뮤직스트림 시연 웹 — 기능 정의서 (v0.1 초안)

| 항목 | 내용 |
|---|---|
| 목적 | 분석 결과(모델 A + 일괄 보정)가 **이용자 화면에서 어떻게 보이는지** 시연하는 웹 페이지의 기능을 정의 |
| 독자 | 화면 기획·디자인·개발을 맡는 팀원 |
| 기준 자료 | `최종보고서`(분석 결과), `데이터명세서_v11.xlsx`, 초안 `web/musicstream-demo.html` |
| 상태 | 초안. 9장의 미결 사항을 정하면 v1.0으로 확정 |

## 1. 확정된 결정

| # | 결정 | 내용 |
|---|---|---|
| D1 | 곡 제목 | `song_extra_info.csv`(2,295,971곡)를 사용. 평가 구간 후보곡의 제목 연결률은 99.9% 이상(전체 파일의 제목 값 결측은 3곡) |
| D2 | 추천 방식 | **기존 추천(보정 없음) ↔ 새로운 발견 추천(일괄 보정)** 두 가지만 비교. 사용자별 차등 보정은 화면에 넣지 않음 |
| D3 | 배포 | Vercel(정적 사이트) |
| D4 | 화면 뒤 설정 비공개 | 보정 강도, 모델 이름, 점수·확률은 **화면과 데이터 파일 어디에도 노출하지 않음** (6.6절) |
| D5 | 모델 실행 | 화면에서 모델을 돌리지 않음. 분석에서 계산한 추천 결과를 JSON으로 만들어 화면이 읽기만 함 |

## 2. 서비스 개요

- **서비스**: 가상의 음악 스트리밍 앱 "뮤직스트림" (시연용)
- **핵심 메시지**: *듣다 보면, 취향이 넓어져요* — 익숙한 노래 사이에 새로운 노래를 살짝 섞어 준다
- **이 시연이 보여 줄 것**: 같은 이용자에게 기존 추천과 새로운 발견 추천이 **어떻게 다르게 보이는지**, 그리고 새로운 곡을 듣도록 유도하는 **발견 미션**
- **이 시연이 보여 주지 않을 것**: 실제 음원 재생, 실제 결제·쿠폰, 실시간 모델 추론, 사용자별 차등 보정

## 3. 핵심 시나리오

| 단계 | 이용자가 하는 일 | 화면에서 일어나는 일 |
|---|---|---|
| 1 | 데모 사용자로 입장 | 시연용 사용자 카드를 고르면 홈으로 이동 |
| 2 | 홈에서 **기존 추천** 10곡을 봄 | 이용자가 평소 듣던 취향 위주의 목록. "추천 갱신까지 0 / 3곡" 표시 |
| 3 | 곡을 3곡 재생(시뮬레이션) | 진행 표시가 3 / 3곡으로 채워짐 |
| 4 | **추천이 새로 구성됨** | 새로운 발견 추천 10곡이 나타나고, 바뀐 곡에 배지가 붙음 |
| 5 | 새로운 발견 곡을 재생 | **발견 미션** 진행 표시가 올라감 |
| 6 | 미션 달성 | 달성 알림과 시연용 쿠폰 |
| 7 | **내 현황**에서 변화를 확인 | 기존 추천 대비 새로운 곡·처음 만나는 가수·숨은 곡이 몇 곡 늘었는지 |

## 6. 추천 데이터 규칙 (화면 표현)

### 6.1 두 추천 목록

| 목록 | 화면 이름 | 분석에서의 대응 |
|---|---|---|
| 목록 1 | 기존 추천 | 모델 A의 점수 순서 그대로 상위 10곡 |
| 목록 2 | 새로운 발견 추천 | 모델 A 점수에 인기도 보정을 적용한 상위 10곡(한도 1%p 설정) |

목록은 데모 사용자별로 **사전에 계산해 JSON으로 저장**합니다. 화면은 두 목록을 보여 줄 뿐이며 점수나 설정은 알지 못합니다.

### 6.2 배지 정의

배지는 곡과 이용자의 **이전 청취 기록**에서 직접 계산되는 사실입니다. 이유 문구도 배지에서만 만듭니다.

| 배지(화면 문구) | 판정 기준(분석의 정의) | 이유 문구 예 |
|---|---|---|
| 처음 만나는 가수 | 이 이용자의 이전 청취에 없는 아티스트(Various Artists 제외) | "처음 듣는 아티스트예요" |
| 숨은 곡 | 평가 구간 시작 전까지의 청취에서 80%를 덮는 인기곡 밖의 곡 | "아직 많이 알려지지 않은 곡이에요" |
| 새로운 장르 | 이 이용자가 처음 듣는 장르 (**장르 이름 표기는 9장 미결**) | "평소 듣지 않던 장르예요" |

> 초안의 "숨은 명곡"은 곡의 질을 보증하는 표현이라 데이터로 뒷받침할 수 없습니다. "숨은 곡"으로 바꾸는 것을 권장합니다.
> 초안의 이유 문구(예: "발라드의 차분한 감성이 비슷해서 골랐어요")는 모델이 만든 설명이 아니라 **지어낸 문장**입니다. 사용하지 않습니다.

### 6.3 변화 요약 지표

| 화면 문구 | 계산 |
|---|---|
| 새로운 곡 N곡 | 새로운 발견 추천 10곡 중 기존 추천에 없던 곡 수 |
| 처음 만나는 가수 N명 | 새로운 발견 추천 10곡에서 "처음 만나는 가수" 배지가 붙은 곡의 아티스트 수 |
| 숨은 곡 N곡 | 새로운 발견 추천 10곡 중 "숨은 곡" 배지가 붙은 곡 수 |

기존 추천의 같은 값과 나란히 보여 줍니다(예: "숨은 곡 1 → 3곡"). 값은 **실제 두 목록에서 계산**합니다.

### 6.4 데모 사용자 선정 기준

- 평가 구간에서 후보곡이 20곡 이상인 사용자 중에서 선정
- **두 추천의 차이가 눈에 보일 것**: 기존 추천과 새로운 발견 추천이 최소 2곡 이상 달라지고, 새로 들어온 곡 중 배지가 붙은 곡이 있을 것
- 사용자마다 취향이 서로 달라 보이도록 3~4명 선정
- 실제 사용자 ID는 화면에 쓰지 않고 "데모 사용자 A" 같은 가명을 사용

### 6.5 데이터 파일 형식 (예시)

```json
{
  "users": [
    {
      "id": "A",
      "name": "데모 사용자 A",
      "topArtists": ["아티스트1", "아티스트2", "아티스트3"],
      "songsHeard": 69,
      "before": [
        { "songId": "…", "title": "곡명", "artist": "아티스트", "minutes": 3.7, "badges": [] }
      ],
      "after": [
        { "songId": "…", "title": "곡명", "artist": "아티스트", "minutes": 3.4,
          "badges": ["newArtist", "hiddenSong"], "reason": "처음 듣는 아티스트예요" }
      ]
    }
  ]
}
```

- 곡명: `song_extra_info.csv`, 아티스트: 원본 통합 데이터의 `artist_name`, 재생 시간: 곡 길이(분)
- 곡 제목에 `|` 같은 문자나 중국어·영어가 섞여 있으므로 화면에서 줄바꿈과 글꼴을 확인할 것

### 6.6 화면과 데이터 파일에 나오면 안 되는 것

| 노출 금지 | 이유 |
|---|---|
| 보정 강도와 설정값, 정확도 손실 한도 | 화면 뒤 설정 비공개(D4) |
| 모델 이름·구조(LightGBM, 앙상블 등) | 동일 |
| 정책 이름·번호("일괄", "차등", "정책 2") | 동일 |
| 예측 확률, 모델 점수, 순위 점수 | 개발자 도구로 JSON을 열면 보이므로 **데이터 파일에 아예 넣지 않음** |
| 사용자 유형의 기술 명칭과 기준값 | 시연에서 유형을 쓰지 않으므로 필요 없음 |
| 실제 사용자 ID(`msno`) | 개인 식별 방지, 가명만 사용 |

이 시연은 정적 사이트라서 **화면에 보이지 않아도 파일에 들어 있으면 누구나 볼 수 있습니다.** 데이터를 만들 때 위 항목을 제거하는 단계를 둡니다.

## 7. 초안(`musicstream-demo.html`) 점검 결과

초안은 모델 완성 전에 만든 **화면 시안**이고, 25개 화면(`#라우트`)과 시연 시나리오가 이미 잡혀 있습니다. 기능 정의서와 비교한 결과입니다.

### 7.1 그대로 쓸 수 있는 것

- 시나리오 흐름: 입장 → 기존 추천 → 3곡 완료 → 추천 갱신 → 새로운 발견 재생 → 미션 달성 → 쿠폰 → 내 현황
- 화면 구성과 문구 톤, "시연용" 표기
- "내 현황"의 비교 지표(새로운 장르 노래, 숨은 곡, 처음 만나는 가수): 분석의 지표와 대응함
- 화면에 설정값이나 모델 이름이 없음

### 7.2 바꿔야 하는 것

| # | 초안 | 변경 |
|---|---|---|
| 1 | 가상의 한국어 곡명·가수(예: 서하준, LUNA K) | 실제 곡명(`song_extra_info.csv`)과 아티스트로 교체. **곡이 중국어·영어 위주**(후보곡 기준 영어 38%, 중국어 25%, 한국어 6%)라서 화면 언어와 어울리는지 확인 |
| 2 | **장르 이름**(발라드, R&B, 인디 등)을 화면 곳곳에서 사용 | **데이터에는 장르 번호만 있고 이름이 없음.** 대체안 필요(9장) |
| 3 | "이 곡이 추천된 이유" 문구가 임의로 작성됨 | 6.2절의 사실 기반 문구로 교체 |
| 4 | 추천 구성 "발라드 80% · R&B 10% · 인디 10%"가 하드코딩 | 실제 목록에서 계산. 장르 이름이 없으면 다른 표현으로 대체 |
| 5 | 가입 시 고른 장르가 추천에 쓰인다는 설명 | 우리 추천은 가입 장르와 무관하므로 연출 문구를 제거하거나 수정 |
| 6 | 미션 기준 혼재: "3곡 완료"(추천 갱신)와 "30분 청취"(보상) | 기준을 하나로 정리(9장) |
| 7 | 추천 갱신 결과가 고정 화면 | 데모 사용자별 사전 계산 결과로 교체 |
| 8 | 비교 보기(기존 ↔ 발견 나란히) 없음 | 추가(F-15) |

### 7.3 구현 방식의 위험

- 3,213줄(약 495KB)은 대부분 **인라인 스타일이 붙은 화면 마크업**이고, 자바스크립트는 약 90줄뿐입니다. 그중 `render` 함수가 **화면의 문구를 정규식으로 찾아서 바꿉니다**(예: "12분 40초 / 30분"). 문구를 바꾸면 동작이 깨지기 쉽습니다.
- 곡·사용자 데이터를 화면 안에 직접 써 놓은 구조라서 **데이터를 JSON으로 분리하고 화면을 데이터로 그리는 구조**로 바꿔야 실제 추천 결과를 넣을 수 있습니다.
- 레이아웃이 데스크톱 폭 위주로 보이므로 모바일 폭에서 확인이 필요합니다.

## 8. 비기능 요구

| 항목 | 요구 |
|---|---|
| 배포 | Vercel 정적 배포. 서버·데이터베이스 없음 |
| 데이터 | 추천 결과 JSON 파일(데모 사용자 3~4명, 수 KB~수십 KB)을 정적 파일로 제공 |
| 시연 표기 | 모든 화면에서 시연용임을 알 수 있는 표기 유지(쿠폰·계정 포함) |
| 반응형 | 데스크톱과 모바일 폭 모두에서 사용 가능 |
| 개인정보 | 실제 사용자 ID·청취 기록 원본을 화면과 파일에 넣지 않음 |
| 성능 | 첫 화면 로딩 시 JSON 하나로 충분하도록 구성 |
| 접근성 | 버튼 `aria-label`, 대비, 키보드 이동(초안 수준 유지) |

## 9. 미결 사항 (확정이 필요한 것)

| # | 질문 | 현황·제안 |
|---|---|---|
| Q1 | **장르 이름을 어떻게 표기할까?** | 데이터에 장르 이름이 없어 번호(예: 465, 359)뿐입니다. 제안: ① 장르 표기를 화면에서 빼고 "새로운 장르" 배지만 사용 ② 아티스트 기준 표현으로 대체("처음 만나는 가수") ③ 팀이 장르 번호에 이름을 직접 붙임(작업량 큼, 근거 필요) |
| Q2 | **발견 미션 기준** | 초안은 "새로운 발견 30분 청취". 시연이 길어지므로 제안: **새로운 발견 곡 3곡 완료**. 팀원 보고서의 미션도 "발견 곡 3곡" 기준 |
| Q3 | 쿠폰·혜택 내용 | 초안은 "월정액 5% 할인". 시연용으로 유지 여부. 분석은 혜택의 효과를 검증하지 않았음 |
| Q4 | 데모 사용자 수와 구성 | 3~4명 제안. 팀의 시연 시간에 맞춰 결정 |
| Q5 | 검색·라이브러리 포함 여부 | 선택 사항(S9~S12). 시간이 부족하면 제외 가능 |
| Q6 | 화면 언어 | 곡 제목이 중국어·영어 위주. 화면 문구는 한국어로 하되 곡명은 원문 그대로 표시할지 |
| Q7 | 재생 완료 기준 | 재생 바 100%인지, 일정 비율(예: 80%)인지 |

## 10. 진행 순서 제안

1. 9장의 Q1·Q2를 먼저 확정(화면 구성에 영향이 큼)

3. 초안을 **데이터로 그리는 구조**로 재작성(필수 화면 S1~S7 우선)
4. 비교 보기(S4)와 변화 요약(F-16) 추가
5. 선택 화면(S8~S12) 보완
6. Vercel 배포와 모바일 폭 점검
