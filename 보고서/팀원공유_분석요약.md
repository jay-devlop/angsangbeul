# 음악 추천 다양화 분석 — 팀원 공유용 요약

> 읽는 시간 약 10분. 자세한 내용은 `B/최종보고서.html`에 있습니다. 이 문서는 "무엇을 어떻게 했는지"만 빠르게 파악하기 위한 지도입니다.

## 1. 한 줄 요약

**재청취 확률을 예측하는 모델(모델 A)을 만들고, 그 점수를 살짝 조정(보정)해서 "정확도를 조금만 내주고 새로운 발견 곡을 늘릴 수 있는지" 확인했습니다.**
결과: 재청취율을 약 1%p 내주면 새로운 발견 곡이 10곡당 **+0.31곡(+10%)** 늘었습니다. 사용자 유형별로 보정을 달리하는 **차등 보정은 일괄 보정보다 추가 이익이 +0.4%** 로 아주 작아서, **일괄 보정을 먼저 쓰자**는 결론입니다.

## 2. 전체 흐름

```
원본 데이터(data.csv)
  ↓ ① 파생변수 129개 만들기
  ↓ ② 모델 A 학습: "이 사용자가 이 곡을 한 달 안에 다시 들을 확률"
  ↓ ③ 사용자별로 후보곡을 확률 순으로 정렬 → 상위 10곡이 기본 추천
  ↓ ④ 보정 B1(인기도)·B2(취향 확장)로 순위 조정
  ↓ ⑤ 정책 3가지 비교: 보정 없음 / 모두에게 같은 보정 / 유형별 다른 보정
```

## 3. 데이터

| 항목 | 값 |
|---|---|
| 원본 | 7,352,114행(사용자가 곡을 들은 기록), 30,751명, 356,267곡 |
| 정답 `target` | 한 달 안에 그 곡을 다시 들었으면 1 |
| 시간 | 타임스탬프가 없어 **행 순서**를 시간으로 사용 |
| 모델용 구간 | 전체의 20~100% (0~20%는 특성 계산용 과거 기록) |
| 분할 | 학습 20~60%, 검증 60~80%, 평가 80~100% (무작위로 섞지 않음) |

## 4. 모델 A (v11)

- **LightGBM 2종 + XGBoost + CatBoost**의 예측을 로지스틱 회귀로 합친 앙상블(Stack4).
- 입력은 **파생변수 129개**.

| 그룹 | 개수 | 쉬운 설명 |
|---|---|---|
| 곡·회원 속성 | 13 | 곡 길이, 장르, 언어, 나이, 성별, 멤버십 기간 |
| 누적 행동 | 17 | 지금까지 이 사용자·곡을 몇 번 들었나 |
| 최근성 | 20 | 최근 얼마나 자주 들었나, 마지막으로 들은 지 얼마나 됐나 |
| 지연 정답 재청취율 | 17 | 과거에 이 사용자·곡을 얼마나 다시 들었나 |
| 취향 유사도(SVD) | 4 | 이 사용자의 취향과 이 곡이 얼마나 비슷한가 |
| 노출 경로 | 20 | 곡을 어느 탭·화면에서 재생했나 (`source_*`) |
| 라이브러리·라디오 성향 | 11 | 내 보관함/라디오로 얼마나 듣나 |
| 경로 프로필 | 27 | 곡·사용자가 탭별로 어떻게 재생되나 |

**누수를 막는 두 가지 규칙** (이게 제일 중요합니다)
1. 특성은 **현재 행 직전까지의 기록**만 사용합니다. 미래 기록은 쓰지 않습니다.
2. 정답(`target`)을 쓰는 특성은 현재 행보다 **43%(약 한 달) 이상 앞선 행의 정답**만 씁니다. 한 달이 지나야 정답이 확정되기 때문입니다.

**성능**: 평가 구간 AUC **0.709** (인기도 기준선 0.575). 예측 확률이 실제 재청취율과 거의 맞습니다(평균 예측 0.402 대 실제 0.404).

> ⚠️ **노출 경로(`source_*`)를 모델 입력에 사용했습니다.** 원본 명세서의 "모델 입력 제외" 비고와 다르니, 팀 문서를 맞출 때 참고해 주세요.

## 5. 보정 (B1·B2)과 정책

모델 A의 **점수는 그대로** 두고, 상위 10곡을 고르는 **순서만** 바꿉니다. 모델을 새로 학습하지 않습니다.

| 이름 | 하는 일 | 예시 |
|---|---|---|
| **B1 인기도 보정** | 인기곡 점수를 깎아 비인기곡을 위로 올림. `조정 점수 = 모델 점수 − λ × 인기도 백분위` | λ=0.2일 때 곡 X(점수 0.60, 인기 0.9)는 0.42, 곡 Y(0.55, 비인기 0.1)는 0.53 → Y가 1위 |
| **B2 취향 확장** | 상위 10곡 중 k곡을 "처음 듣는 장르"의 곡으로 채움. 예측 확률이 τ 이상인 곡만 | k=2, τ=0.4: 9~10위를 새 장르 곡 2개로 |

| 정책 | 내용 |
|---|---|
| 정책 1 | 모델 A 그대로 (보정 없음) |
| 정책 2 (일괄) | 모든 사용자에게 같은 B1·B2 |
| 정책 3 (차등, B3) | 사용자 유형별로 B1·B2 강도를 다르게 |

**사용자 유형 3가지** (이전 청취 이력만으로 구분)
- **탐색 친화형**: 낯선 곡(새 아티스트·새 장르)을 다시 듣는 비율이 높은 사람
- **익숙함 선호형**: 낯선 곡을 잘 안 다시 듣는 사람
- **판단 유보형**: 정답이 확정된 청취가 20회 미만이라 판단하기 어려운 사람

## 6. 평가 지표

| 지표 | 뜻 |
|---|---|
| Top-10 재청취율 | 추천 10곡 중 실제로 다시 들은 곡 비율 (정확도) |
| **유효 발견@10** | 추천 10곡 중 **비인기곡·새 아티스트·새 장르 중 하나이면서 실제로 다시 들은 곡** 수 (보정의 진짜 이익) |
| 비인기곡 | 구간 시작 전까지의 청취 중 **80%를 차지하는 상위 곡 밖**의 곡 (평가 후보의 약 28%) |
| 손실 한도 | 보정으로 내줄 수 있는 재청취율의 최대치 (팀 기준 1%p, 분석에서는 1·2·3·5%p 시험) |

평가 대상은 **후보 20곡 이상인 사용자**(평가 구간 15,080명)이고, 후보곡은 그 사용자가 평가 구간에서 **실제로 재생한 곡**입니다.

## 7. 핵심 결과 (평가 구간)

| 항목 | 결과 |
|---|---|
| 일괄 보정, 한도 1%p | 재청취율 −1.02%p, 유효 발견 3.10 → 3.40곡 (**+10%**) |
| 일괄 보정, 한도 2%p | 재청취율 −1.47%p, 유효 발견 3.10 → 3.49곡 (+13%) |
| 차등 − 일괄 (노출을 맞춘 비교) | 한도 1%p **+0.015곡(+0.4%)**, 한도 2%p +0.029곡(+0.8%) |
| 유형 정의 6가지 비교 | 어떤 정의를 써도 추가 이익이 0~2%대. 일관되게 더 나은 방식 없음 |

**결론**: 차등 보정이 통계적으로는 조금 더 낫지만 이익이 작아서, 유형을 관리하는 비용을 감수할 만큼은 아닙니다. **일괄 보정(B1 중심)을 먼저 적용하고, 차등은 실서비스 A/B 테스트로 확인된 뒤에 도입**하자는 권고입니다.

가설 H1~H4는 H1·H4 지지되지 않음, H2 약하게 지지, H3 인기 편향 측면에서만 지지였습니다. 즉 "다양성이 활동 유지로 이어진다"는 근거는 이 데이터에서 약했습니다.

## 8. 파일 지도

```
음악 추천/
├─ data.csv                    원본 통합 데이터
├─ A/                          모델 개발(v1~v12) 코드와 결과
│   └─ v11/                    ★ 최종 모델 A (Stack4)
├─ B/                          보정·정책 분석
│   ├─ 최종보고서.html          ★ 최종 결과 보고서
│   ├─ 데이터명세서_v11.xlsx    ★ 모델 입력 데이터 명세서
│   ├─ b1_hypotheses.py        가설 H1~H4 분석
│   ├─ b2_policies.py          B1·B2·정책 비교
│   ├─ b3_types.py             사용자 유형 정의 6가지 비교
│   └─ results/                분석 결과 파일(JSON, CSV)
```

**실행 순서**: `A/v11.py`(모델, 약 94분) → `B/b1_hypotheses.py` → `B/b2_policies.py`(약 5분) → `B/b3_types.py` → `B/make_report.py`(보고서 생성).
> `A` 폴더로 옮긴 코드는 `data.csv` 경로를 `../data.csv` 등으로 고쳐야 합니다. 필요한 패키지: lightgbm, xgboost, catboost, scikit-learn, pandas, pyarrow, scipy, openpyxl.

## 9. 알아둘 점 (한계)

- **평가 구간을 모델 개발 중 여러 번 확인**했습니다. 보정 설정은 검증 구간에서만 골랐지만 평가 수치에는 약간의 낙관 편향이 있을 수 있습니다.
- **후보곡이 이미 들은 곡**입니다. "새 곡을 추천했을 때"의 반응은 측정하지 못했습니다.
- **정답 지연 규칙은 특성에만 적용**했고 학습 자체에는 적용하지 않아, 실서비스 성능은 다소 낮을 수 있습니다.
- 비인기곡 기준(80%)과 보정 강도 후보 범위는 **우리가 정한 값**이라, 바꾸면 수치가 달라질 수 있습니다.
- 팀원 보고서와는 **노출 경로 사용 여부와 비인기곡 기준이 달라** 수치를 직접 비교하면 안 됩니다.
- 선행 연구의 서지는 제출 전에 원문 확인이 필요합니다(보고서 부록 F에 상태 표시).

## 10. 용어 사전

| 용어 | 뜻 |
|---|---|
| 재청취율 | 한 달 안에 같은 곡을 다시 들은 비율 |
| AUC | 예측 순위 성능. 0.5는 무작위, 1에 가까울수록 좋음 |
| ECE | 예측 확률이 실제 비율과 얼마나 어긋나는지. 작을수록 좋음 |
| 앙상블 / 스태킹 | 여러 모델의 예측을 합치는 방식 |
| λ, k, τ | 보정 강도(B1), 바꿀 곡 수(B2), 최소 예측 확률(B2) |
| 노출 맞춤 비교 | 두 정책이 발견 대상곡을 같은 양 노출하도록 맞춰서 공정하게 비교하는 방식 |
| 95% 신뢰구간 | 사용자 단위로 다시 뽑아 구한 오차 범위. 0을 포함하지 않으면 차이가 의미 있음 |
